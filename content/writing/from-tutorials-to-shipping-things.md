I got into tech unofficially during my JSS3 school break.

My dad wanted us to learn basic computer skills, so I started with desktop publishing. At the time, there wasn't some grand plan to become a developer or build software. I was just learning how to use a computer.

By SS1, one of my lesson teachers introduced me more seriously to science and computers. Somewhere around that time I became fascinated by computer hacking. I wanted to understand how it worked, but I had no idea where to begin.

There was so much to learn and everything I found felt scattered.

Eventually, I figured out that if I wanted to understand cybersecurity, I probably needed to learn programming first.

## Learning to code without knowing what coding was for

One day at a cyber café, I was Googling how to learn programming when a Python developer noticed what I was doing.

He introduced me to W3Schools and gave me a Python video series on a USB drive.

I finished the series.

And then… I didn't know what to do with any of it.

I could follow the lessons and write some Python, but I couldn't see how any of that became actual software that somebody could use. At this point, I didn't even understand concepts like frontend and backend.

I just knew I wanted to build things.

So I kept learning.

HTML. CSS. Bootstrap. Eventually Tailwind CSS. Somewhere in there, SCSS too.

And a lot of tutorials.

**A lot.**

For years I was basically stuck in tutorial hell. I would learn something, stop, return to those Python videos, try again, get frustrated and sometimes give up completely.

Then eventually start again.

## Seeing people actually ship

Things started changing when I discovered LinkedIn.

Early on, I came across a post from the founder of GenZTechies and connected with him. What happened through that community is probably a story of its own, but one thing had a big effect on me:

**I saw people actually building things.**

Not another calculator.

Not another to-do app copied from a tutorial.

People around me were building useful software. Some were creating internal tools and selling them to companies.

That changed what I wanted from programming.

I didn't just want to know how to code anymore. I wanted to be able to take an idea and turn it into something real—something useful enough that another person would actually want to use it.

The problem was that wanting to build useful products and being able to build them were still two very different things.

I struggled with that gap for a long time.

## Then AI showed up

AI-assisted development changed that gap for me.

Not because I suddenly stopped needing to understand anything, and definitely not because every output from an AI is good software.

What changed was my ability to move.

Things that previously left me searching through tutorials, documentation and scattered Stack Overflow answers for hours could become conversations. I could ask questions about code I didn't understand, explore an implementation, break something, figure out why it broke and keep going.

More importantly, I could spend more time thinking about the thing I was trying to make.

How should it work?

What should it look like?

Would anyone actually find this useful?

How do I get it from an idea to something running on somebody else's device?

Design became part of that too.

I've watched designers and builders I admire—people like Dára—move across the boundary between designing software and engineering it, increasingly using AI as part of that process.

It reinforced something I'd slowly been learning myself: the boundaries aren't as important as the ability to make something good.

## I still don't think the goal is to write more code

Today I'm shipping more than I used to.

Websites. Experiments. Side projects. Products I'm trying to turn into genuinely useful software.

I'm still learning, and there are plenty of things I can't build without assistance. AI hasn't magically replaced all those years I spent struggling with programming.

But it has changed how I learn and, more importantly, how often learning can end with something **shipped**.

Looking back, that's probably the biggest difference between the kid replaying Python videos from a USB drive and how I think about technology now.

Back then, I thought learning programming meant eventually knowing enough to start building.

I don't think that anymore.

**You learn a lot of it by building.**

And these days, I'm much more interested in what I can make useful than in how many technologies I can say I know.
